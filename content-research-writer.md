# Content Research Writer

## Purpose

The end-to-end workflow for going from idea to a published LinkedIn post. This skill combines research, voice, and best practices into a repeatable, improvable process.

---

## Phase 0 — Ideation

Before writing, the idea must be validated. An idea is a candidate; a validated idea is a post worth writing.

**Idea sources (pull from any):**
- Supermemory: topics that performed well but haven't been revisited
- Deep research: gaps competitors aren't covering
- Personal experience: a lesson learned, mistake made, result achieved
- Trending topics: something rising in the niche in the last 7 days
- Audience comments: questions your audience is asking repeatedly
- Content pillars (see below)

### Content Pillars

Every post should map to one of these pillars:

| Pillar              | Description                                            | Example Topics                          |
|---------------------|--------------------------------------------------------|-----------------------------------------|
| **AI & Tools**      | Practical use of AI for work and building              | AI workflows, prompting, automation     |
| **Building**        | The process of creating products, companies, content   | Shipping, failure, iteration, decisions |
| **Thinking**        | Mental models, frameworks, and ways of seeing clearly  | Decision-making, clarity, biases        |
| **Career & Growth** | Professional development, leverage, skills             | Learning, positioning, leverage         |
| **Contrarian**      | Challenging mainstream advice with evidence            | Debunking myths, hard truths            |

**Rule:** Rotate across pillars. Don't post from the same pillar 3 times in a row.

---

## Phase 1 — Research Brief

Fill out the research brief before writing any draft. Never skip this.

```markdown
## Research Brief

**Post topic:** [one sentence]
**Pillar:** [AI & Tools | Building | Thinking | Career & Growth | Contrarian]
**Core claim / thesis:** [the one argument this post makes]
**Proof or anchor:** [specific stat, story, example, or data point]
**Hook pattern:** [from hook library in supermemory]
**Target reader:** [specific person — their role, problem, or mindset]
**Competing posts found:** [what's already out there on this topic?]
**Differentiated angle:** [what makes this post different from existing content?]
**Post format:** [story | list | framework | hot take | curation | question]
**Estimated length:** [short / medium / long]
**Closer / CTA:** [what should the reader think, feel, or do after reading?]
```

---

## Phase 2 — Hook-First Drafting

Write the hook before writing the body. A weak hook = no post.

### Hook Writing Protocol

1. Write 5 different hooks for the same post
2. Score each hook: Does it create curiosity? Does it make a bold claim? Does it promise value?
3. Select the strongest one
4. Test it with the "scroll test": Would you stop scrolling if you saw this on your feed?

**Hook evaluation rubric:**

| Criterion            | Question                                          |
|----------------------|---------------------------------------------------|
| Specificity          | Does it name a number, person, or thing?          |
| Tension              | Does it create a gap the reader wants to close?   |
| Relevance            | Does it speak directly to the target reader?      |
| Originality          | Is it different from what's already in the feed?  |
| Voice match          | Does it sound like Celsux?                        |

---

## Phase 3 — Body Drafting

With the hook locked, write the body.

### Writing Principles

1. **One idea per post.** If you're making two points, that's two posts.
2. **Lead with the conclusion.** Don't bury the insight at the end.
3. **Show, don't tell.** Use specifics — a number, a name, a scene — instead of vague claims.
4. **Flow test.** Each paragraph should make the reader want to read the next one.
5. **Cut the first paragraph.** Most drafts have an unnecessary warm-up paragraph. Delete it.

### Body Structure Templates

**Story format:**
```
[Hook: the moment of tension or change]
[The setup: what was happening, what I believed]
[The turning point: what I discovered or did]
[The lesson: one clear takeaway]
[The implication: what this means for the reader]
```

**List format:**
```
[Hook: the promise]
[Brief context: why this list matters]
[Item 1: key word first. then the explanation.]
[Item 2: key word first. then the explanation.]
[…up to 7 items]
[Closer: the synthesis or the challenge to the reader]
```

**Framework format:**
```
[Hook: the problem this framework solves]
[The framework name and what it does]
[Step/layer 1: explained simply]
[Step/layer 2: explained simply]
[Step/layer 3: explained simply]
[When to use it and when not to]
[Closer: a question or a challenge]
```

**Hot take format:**
```
[Hook: the bold claim]
[The conventional wisdom: what most people believe]
[The evidence against it: specific and credible]
[The reframe: how to think about it instead]
[Closer: invite pushback or reflection]
```

## Phase 4 — Voice Pass

After drafting, apply the Celsux voice filter. Read the post out loud.

**Voice pass checklist:**
- [ ] Does the first sentence punch hard?
- [ ] Is there any corporate jargon? Replace it with plain language.
- [ ] Are there passive voice constructions? Make them active.
- [ ] Any unnecessary hedging ("I think", "maybe", "sort of")? Cut it.
- [ ] Does each line earn its place?
- [ ] Is the tone consistent throughout — not switching between formal and casual?
- [ ] Does it sound like something Celsux would genuinely say?

---

## Phase 5 — Format Pass

Apply the formatting rules from best-practices.

**Format pass checklist:**
- [ ] Line breaks after every 1-3 sentences
- [ ] No paragraph longer than 3 lines
- [ ] Hook is 2 lines or fewer
- [ ] External link is NOT in the body
- [ ] Maximum 3 hashtags, all relevant
- [ ] Bold used once (the most important phrase)
- [ ] Emojis used sparingly or not at all

---

## Phase 6 — Pre-Publish Review

Final review before the post goes live.

**Ask these questions:**
1. If I were a stranger scrolling LinkedIn, would I stop for this hook?
2. Would I read the whole thing?
3. Would I comment, save, or share it?
4. Is there one clear takeaway I'll remember an hour from now?
5. Does this represent the brand well?

If any answer is "no" or "I'm not sure," go back to the relevant phase.

---

## Phase 7 — Publish & Engage

Posting is not the end of the workflow. The engagement window is critical.

**Publication protocol:**
1. Post at optimal time (from analytics — see best-practices)
2. Immediately go to your feed and engage on 5-10 other posts (warms the algorithm)
3. Come back within 30 minutes and reply to every comment
4. Add the link to a comment if external link is needed
5. Pin the best comment if one appears in the first hour

---

## Phase 8 — Log to Supermemory

After 48 hours, log the post performance.

1. Pull metrics: impressions, reactions, comments, reposts
2. Calculate engagement rate
3. Assign a performance tier (A / B / C)
4. Write qualitative notes: what worked, what didn't, what the comments revealed
5. Add to the hook library if the hook was exceptional
6. Flag any topic or angle worth revisiting

---

## Full Workflow Summary

```
Phase 0: Ideation        → Pick a validated idea from content pillars / research
Phase 1: Research Brief  → Fill out the brief — no writing without it
Phase 2: Hook First      → Write 5 hooks, pick the best one
Phase 3: Body Draft      → Write to structure, lead with conclusion
Phase 4: Voice Pass      → Apply Celsux voice filter, read aloud
Phase 5: Format Pass     → Apply formatting rules
Phase 6: Pre-Publish     → Final review — stop if any answer is "no"
Phase 7: Publish         → Post, warm algo, reply within 30 min
Phase 8: Log Memory      → Log to supermemory after 48h
```

## Time Budget Per Post

| Phase               | Time Estimate     |
|---------------------|-------------------|
| Ideation            | 5-10 min          |
| Research brief      | 10-20 min         |
| Hook writing (5)    | 10 min            |
| Body draft          | 20-30 min         |
| Voice + format pass | 10 min            |
| Pre-publish review  | 5 min             |
| **Total**           | **~60-75 min**    |

Batching (writing multiple posts in one session) reduces this by ~30%.
